Kyrax 1.0.5 publication path

1. Commit and push the implementation to main without a version tag.
2. Set `version = "1.0.5"` in Cargo.toml and refresh Cargo.lock.
3. Run the release gates and build metadata checks.
4. Commit the release bump as `Release 1.0.5` and push main.
5. Create and push the immutable tag: `git tag v1.0.5` then
   `git push origin v1.0.5`.
6. The tag triggers `.github/workflows/release.yml`, which builds wheels and
   the source distribution, publishes them to PyPI with the repository secret
   `PYPI_API_TOKEN`, and creates the GitHub Release.
7. Verify the workflow, https://pypi.org/project/kyrax/1.0.5/, and a clean
   installation in a fresh environment.

Never retry by reusing a partially published version number: PyPI artifacts
are immutable. Fix the release and use the next version if any 1.0.5 artifact
has already reached PyPI.
